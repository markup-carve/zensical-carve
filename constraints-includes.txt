# The engine the `includes` CI job measures.
#
# `carve.render_with_includes` is on carve-py main and in no published
# carve-lang, so `constraints-ci.txt` cannot name it: that file pins a PyPI
# version, and every version PyPI serves predates the entry point. Until a
# release carries it, the include tests need a revision instead.
#
# A direct-URL requirement is what `pyproject.toml` deliberately does NOT
# declare - PyPI refuses a distribution that has one. Keeping it here means CI
# can measure the entry point while the published package stays installable.
#
# Retire this file when a carve-lang release carries `render_with_includes`:
# raise the pin in `constraints-ci.txt` instead, and the `includes` job folds
# back into the matrix job.
